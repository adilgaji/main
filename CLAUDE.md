# Фабрика исторических видео — правила проекта

Локальная фабрика длинных (8–9 минут) горизонтальных YouTube-видео по ИСТОРИИ.
Владелец — не программист: всё объяснять **просто и по-русски**. Сами видео — **на английском**.

План и текущий статус: `docs/PLAN.md` (блоки A–D). После каждого блока — запуск, тест,
показ результата и ожидание «ок» владельца. Не переходить к следующему блоку без «ок».

## Экономия лимита (у владельца подписка Pro — это важно)

- Один блок плана = одна новая сессия. Не тащить длинный контекст.
- Писать код крупными кусками сразу с автотестами; проверять `pytest`, `npm run check` и
  скриптами, а не разглядыванием картинок. На блок — не больше 1–2 просмотров изображений.
- Не делать страниц-артефактов и длинных отчётов: файлы отправлять напрямую, отчёт — до
  10 строк.
- Не ходить из облака на сайты, которые не пускают роботов (см. ниже). Для тестов — тема
  «Фермопилы» с уже открытыми источниками.
- Не читать заново документацию и чужой код, если нужное уже записано в этом файле.
- Не добавлять новые библиотеки без необходимости.

## Жёсткие ограничения

- Только бесплатные инструменты, всё работает локально на ноутбуке владельца
  (Windows 11, NVIDIA RTX 4050 Laptop 6 ГБ). Никаких платных API, подписок,
  внешних генераторов картинок / видео / голоса.
- Единственный «умный» компонент — Claude Code: субагенты через `claude -p --agent <имя>`.
- Музыки НЕТ. Только голос. Звуковые эффекты — только если владелец попросит.
- Видео: английский, 8–9 минут (≈1250–1400 слов озвучки), 16:9, 1920x1080, 30 fps.
- Shorts: 3–5 штук, 30–55 с, 1080x1920, **пересобираются** вертикально, а не обрезаются.
- Автозагрузки на YouTube нет: финальный просмотр делает владелец.
- Ответы владельца из ТЗ не переспрашивать.

## Стек

- **Remotion (React)** — папка `video/`. Следовать правилам skill `remotion-dev/skills`
  (`.claude/skills/`).
- **Python 3.12** (Kokoro не работает на 3.13+), отдельный `.venv`.
- **Озвучка Kokoro** (`kokoro==0.9.4`). Время каждого слова — прямо из Kokoro
  (`result.tokens`: `start_ts` / `end_ts`).
  **НИКОГДА не использовать faster-whisper / ctranslate2**: Smart App Control в Windows 11
  блокирует их DLL (WinError 4551). Запасные движки: Piper, затем edge-tts.
- **Произношение**: словарь `config/pronunciations.json`; misaki принимает запись
  `[слово](/фонемы/)`. Все имена собственные в тексте проверяются и добавляются в словарь.
- **FFmpeg** — сборка, громкость, проверки.
- **Веб-страница**: FastAPI + один HTML-файл, запуск двойным щелчком `start.bat`.
- GPU — там, где ускоряет, с автоматическим откатом на CPU при любой ошибке.

## Озвучка: как это устроено (этап 1)

- Код: `factory/tts/`. Главная функция — `factory.tts.narrate_to_files(text, wav, voice=…)`:
  пишет WAV и рядом `.words.json` со временем каждого слова.
- Слова со временем обязаны в точности совпадать со словами текста после
  `factory.tts.text.normalize()` — движок сам это проверяет и падает при расхождении.
- Словарь: `config/pronunciations.json`, для каждого слова два варианта — `us` (голоса `a*`)
  и `gb` (голоса `b*`). Ключ — одно слово. Команды:
  `python -m factory.tts.cli check | audit ФАЙЛ | phonemes "текст" | add СЛОВО --us … --gb …`.
- `audit` показывает слова, которые Kokoro «угадал» (нет ни в его словаре, ни в нашем).
  Каждое такое имя собственное агент обязан проверить и добавить в словарь.
- Римские цифры после имени читаются сами («Thutmose III» → «the Third», «World War II» →
  «Two»). Исключение — одиночная «I»: её легко спутать с местоимением, поэтому в тексте
  озвучки писать «Darius the First», а не «Darius I».
- Темп у голосов разный (144–175 слов/мин), поэтому число слов на 8–9 минут считается от
  темпа выбранного голоса, а не берётся жёстко 1250–1400.
- Модели лежат в `models/` внутри проекта (не в профиле пользователя); когда они скачаны,
  озвучка работает без интернета.
- Версии библиотек зафиксированы: `requirements.in` → `requirements.txt` (собран для Windows).
- Проверка записей распознаванием речи (Whisper) делалась только при разработке и в продукт
  не входит.

## Видео: как это устроено (этап 2)

- Проект Remotion — `video/`. Всё содержимое приходит данными: композиция `Chapter`
  получает список кадров, слова со временем и файл озвучки через `--props` (см.
  `scripts/make_library_demo.py` — уменьшенная копия сборки главы).
- Типы кадров — `video/src/shots/` (реестр в `index.tsx`): `map`, `timeline`, `kenburns`,
  `quote`, `infographic` (areas / bars / number), `narrator`. Новый тип = компонент + строка
  в реестре.
- Слои кадра задаёт `ShotFrame`: картинка (к ней применяется обработка стиля) → зерно и
  затемнение краёв → текст. Любая надпись идёт в слой `text`, иначе обработка её размоет.
- Если надписи привязаны к точкам картинки (карта, таймлайн), движение камеры на слой
  картинки не вешать: слои разъедутся. На карте камера своя, внутри `MapShot`.
- Надписи ставятся только в `LABEL_AREA` (внутри полей и выше полосы субтитров) —
  `video/src/lib/labels.ts`. Карта сама раскладывает подписи без наложений; та, которой не
  нашлось места, не показывается. Участок карты из раскадровки вписывается в эту же область.
- Анимация — только от номера кадра (`useCurrentFrame` + `interpolate`), без CSS-переходов.
- Шрифты — локальные файлы в `video/public/fonts` (SIL OFL), грузятся через
  `@remotion/fonts`. Кадр не рисуется, пока шрифты не загружены: иначе текст измерится
  запасным шрифтом.
- Файлы из `public/` (данные карт, текстуры) грузить через `lib/assets.ts`: пауза рендера
  ставится сразу при первом вызове, а не в `useEffect`, иначе кадр снимается раньше загрузки.
- Карты: Natural Earth в `video/public/geo` (сборка — `node scripts/build-geo.mjs`).
  В данных 10m есть многоугольники с обратным обходом — их чинит `repairPolygons`; без этого
  суша заливает всю карту.
- Субтитры: страница не пересекает границу предложения, строки выравниваются по длине
  (`buildPages` в `components/Captions.tsx`).
- Вес файла: «живое» зерно плохо сжимается. Зерно меняется раз в 3 кадра (`grainEvery`),
  рендер с `--crf=22` — около 5,5 Мбит/с, то есть ≈350 МБ на 8,5 минуты.
- Скорость рендера в облаке (4 ядра, без видеокарты): 6–10 кадров/с в зависимости от
  кадра (карта и рассказчик медленнее, цитата быстрее) — то есть 8,5 минуты видео ≈ 25–40
  минут. Режимы `swiftshader`, `egl` и `angle-egl` дают одинаковую скорость.
- Картинки и текстуры ставить тегом `<Img>` (текстуры — через `components/Tiled.tsx`),
  а не CSS `background-image`: так требует правило Remotion, и кадр ждёт загрузки файла.
- У композиции `<Still>` частота кадров равна 1 — всё, что считается через `fps`, в ней
  ломается. Листы-образцы регистрировать как `<Composition durationInFrames={1}>`.
- При склейке картинки и звука не использовать `-shortest` (теряются кадры): звук
  дополняется тишиной (`-af apad -t <длина>`), затем проверка «кадров столько, сколько
  ожидалось, и звук = картинка».
- Браузер для рендера Remotion скачивает с `remotion.media`. В облаке Node не видит прокси
  сам: `NODE_USE_ENV_PROXY=1 npx remotion browser ensure`.
- Remotion-скиллы лежат в `.claude/skills/` (установлены через `npx skills add
  remotion-dev/skills`). Композиции регистрируются программно: это один шаблон, который
  заполняется данными, а не ролик для ручной правки в Studio.
- Справочные сайты (Britannica, World History Encyclopedia, сайт Метрополитена, Perseus)
  из облака часто отвечают отказом роботам (403 / 429). Программные интерфейсы музеев
  работают. Обходить защиту нельзя; полноценная проверка фактов — с ноутбука владельца.

## Стили: как это устроено (блок A)

- 8 стилей, список и русские названия — `video/src/styles.json` (его читают и Remotion, и Python).
  Сами цвета, шрифты, обработка картинки — `video/src/style.ts`. Стиль = набор настроек, а не
  перерисовка кадров: палитра, 3 шрифта (`families`), `treatment` (фильтр, вуаль `tint`, зерно,
  рисунок `pattern`: сетка / полутона / царапины / прожектор, мерцание), вид субтитров `captions`.
- Договорённость во всех стилях: фон тёмный, бумага светлая, море тёмное, суша светлая — на этом
  держатся подписи на карте и плашки. `node scripts/check-styles.mjs` (входит в `npm run check`)
  проверяет контраст каждой пары «текст / фон», наличие шрифтов, различимость стилей. Новый стиль =
  запись в `styles.json` + `make(...)` в `style.ts` + строка в списке `ALL`.
- Шрифты — `video/src/fontFaces.ts` (все OFL, `public/fonts/LICENSES.md`). Грузятся только
  шрифты выбранного стиля (+ служебный Inter). Для файлов с одним начертанием диапазон «100 900»,
  иначе браузер рисует поддельный жирный.
- Русские надписи для владельца (листы, образцы) — всегда `FONT_SERVICE` (Inter с кириллицей).
- Листы «один кадр в 8 стилях»: композиции `Styles-Image` / `Styles-Map` / `Styles-Quote`
  (`python scripts/styles.py sheets`, рендер со `--scale=2`). Любую композицию можно нарисовать в
  другом стиле: `--props='{"styleId":"newsreel"}'` (`Library-Sheet`, `Character-Sheet`, `Chapter`).
- Основной стиль владельца — `config/settings.json` (`style`; сейчас `museum`). Менять: `python scripts/styles.py
  set <номер|id|название>`. Пока не выбран — `documentary`. `factory.styles.style_of(settings)` → id для рендера.
- **Выбор стиля — первый шаг каждого видео, до запуска производства.** Список из 8 стилей показывается
  владельцу (в чате: списком текстом, «Enter/оставить» = основной стиль; в терминале —
  `python scripts/styles.py pick --video <папка>`; на веб-странице — экран выбора). Ответ пишется в
  `state.json` видео (`overrides.style`, `factory.styles.choose_for_video`). Производство вызывает
  `require_style_chosen(video_dir)` и без выбора не стартует. Агент сам стиль не выбирает и не пропускает шаг.

## Производство: как это устроено (блок B)

- Запуск: `python -m factory.production output/<папка>` (`--no-render` — всё, кроме рендера). На входе
  в папке видео: `script.json` (главы `id/title/text`, `sources`, `facts` со статусами), `storyboard.json`
  (по главам: кадры `{at, transition, shot}`), `state.json` с выбранным стилем. Тест: `python scripts/make_test_video.py
  --style museum` (данные — `scripts/demo/thermopylae/`).
- `at` — первые слова фразы, с которой начинается кадр (у первого кадра главы пусто). Граница кадров — середина
  паузы перед этим словом в реальной озвучке. Правила раскадровки (типы подряд, фоны, длина надписей, 2–10 с на
  кадр, желательно 4–8) — `factory/storyboard.py: validate / duration_problems`.
- Картинка в раскадровке — только ссылка `архив:id` в поле `image` (`src` запрещён). Архивы и проверка лицензий —
  `factory/images/` (`python -m factory.images.cli search "…" | get met:248299 | archives`). В `sources.txt` у каждой
  строки есть «чем подтверждена лицензия». Ответы API кэшируются в `cache/api`, файлы — в `cache/images`.
- Состояние архивов из облака: Met (поиск v1 закрыт 01.10.2026 — используется `/v1.1/search`), AIC (картинки
  до 1686 px), Rijksmuseum (данные на нидерландском), LoC (только `tile.loc.gov`; `cdn.loc.gov` закрыт прокси),
  Commons (часто 429 — ждём `Retry-After` до 60 с, дальше не обходим), Smithsonian — нужен личный бесплатный ключ
  (`config/settings.json → images.smithsonian_api_key`), общий `DEMO_KEY` упирается в лимит.
- Озвучка глав — одним движком на всё видео (`narrate_many`): Kokoro → Piper (`models/piper`, время слов
  внутри фразы рассчитывается) → edge-tts (онлайн, без словаря). Длина главы округляется вверх до кадра,
  громкость выравнивается для всего видео сразу. Готовая озвучка переиспользуется, если текст не менялся.
- Новые типы кадров: `scene` (фон plain/coast/pass/sea + значки из `components/Icons.tsx`), `compare` (две
  половины: картинка или значок), `diagram` (блоки по сетке col 0…3 × row 0…2 и стрелки). Переходы между кадрами
  (`fade/slide/wipe/zoom/cut`, в начале и конце главы — `dip`) — в `Chapter.tsx`; кадры перекрываются на время перехода.
- Рендер: сборка проекта один раз (`remotion bundle`), главы — отдельными файлами в `work/render`, рядом отметка
  `.done.json` с отпечатком (props + код `video/src` + crf): готовые главы не рендерятся заново. Скорость
  этого компьютера запоминается в `cache/render_speed.json` для оценки времени. Модуль склейки — `render/join.py`.
- Проверки (`factory/checks`, отчёт `checks.json`): формат файла и +faststart; кадры = звук = раскадровка;
  громкость; начало голоса в каждой главе против времени первого слова (± 0,25 с); обрезанные слова; `.srt` = текст
  на 100 %; главы ± 1 с; лицензии; соседние кадры; пустые и чёрные кадры (по «наполненности» уменьшенного кадра).

## Агенты и упаковка: как это устроено (блок C)

- Шаги одного видео — `factory/pipeline.py` (`python -m factory.pipeline new | status | run <шаг> | pick N | approve <шаг>`):
  стиль → тема (`idea-researcher`, владелец выбирает номер) → план (`outline-writer`) → текст (`scriptwriter` +
  `fact-checker`, один круг исправлений) → озвучка и раскадровка (`image-researcher` даёт запросы, скрипт ищет в архивах,
  `storyboard-agent`) → производство (без остановки) → упаковка. Шаг стартует, только если предыдущий принят
  (`require`); результат шага — «ждёт решения», владелец: `approve` или `run <шаг> --note «что изменить»`.
- Агенты — `.claude/agents/*.md` (модель и инструменты в заголовке; сильная модель — только `scriptwriter` и
  `fact-checker`). Запуск — `factory/agents.py`: `claude -p --agents <файл> --agent <имя> --json-schema … --tools …
  --permission-mode dontAsk`, из временной папки вне проекта (чтобы не грузить CLAUDE.md). Ответ проверяется схемой
  (`factory/schemas.py`) и правилами; при ошибке — до 3 попыток со списком замечаний. Стоимость пишется в `state.json`.
  В автотестах агенты подменяются (`FACTORY_FAKE_AGENTS=<папка>` или monkeypatch `agents._call`).
- Объём текста считается от темпа голоса: `textcheck.words_target(минуты, голос)` (готовое видео ≈ 1,09 × темп голоса;
  8,5 мин голосом am_fenrir ≈ 1470 слов). Простота — Флеш–Кинкейд ≤ 8,5, предложения ≤ 30 слов, без «subscribe»,
  без «Darius I». Имена, которые Kokoro читает наугад, fact-checker озвучивает фонемами — они сразу пишутся в словарь.
- Память структур — `config/structures.json` (`recent`): агенту плана не даются две последние.
- Упаковка — `factory/packaging.py`: `packager` (3 названия, описание, теги, 3 обложки), файлы `title.txt`,
  `description.txt` (сначала главы «0:00 …», потом текст и источники), `tags.txt`; обложки — композиция `Thumbnail`
  (1280x720, `render.still`); Shorts — `factory/shorts.py`: `shorts-editor` выбирает хук + отрывок одной главы
  (30–55 с), хук озвучивается тем же голосом, звук отрывка вырезается из озвучки видео; композиция `Short`
  (1080x1920). Итог — `quality-reviewer` → `review.json`.
- Вертикальный кадр: «холст» `video/src/lib/canvas.ts` (`HORIZONTAL` / `VERTICAL`). Карта, архивное изображение,
  цитата, рассказчик, текстуры и субтитры берут размеры и поля из него; остальные кадры в Short идут в рамке 16:9.

## Веб-страница и установка: как это устроено (блок D)

- Страница — `factory/web/`: `app.py` (FastAPI), `views.py` (только чтение файлов видео → JSON), `jobs.py`
  (фоновая задача), `index.html` (один файл, без сборки и внешних библиотек). Запуск — `python -m factory.web`
  (`start.bat`), адрес `127.0.0.1:8765`; если страница уже работает, открывается она же (`/api/ping`).
- Долгие шаги идут отдельным процессом `python -m factory.pipeline run|fix …` с логом в `logs/web/`; одновременно —
  одна задача (`Runner`, `Busy`). «Остановить» убивает всё дерево процессов (`taskkill /T` на Windows). Быстрые решения
  (стиль, номер темы, «принять») — сразу через `pipeline.py`. Выбор темы переименовывает папку — страница берёт новый id.
- Защита: отвечает только хостам `127.0.0.1` / `localhost` / `[::1]`, команды (POST) — только с заголовком
  `X-Factory: 1`. Файлы отдаются только изнутри папки видео (`views.safe_file`), картинки архивов — только из кэша.
- Экран стиля режет листы `video/out/styles-*.png` (сетка 3×3) на 8 кнопок-превью; нет листов — кнопка «нарисовать».
- Установка: `setup.bat` (winget: Python 3.12, Node LTS, FFmpeg, Git, Claude Code → после установки новых программ просит
  перезапустить себя; `.venv`, pip, `npm install`, `remotion browser ensure`, модели с Piper, ярлык «History Factory»,
  `check_env.py`). `install_gpu.bat` — `torch==2.15.0+cu132` (у 2.15.0 есть только сборка cu132 → драйвер ≥ 580;
  при смене версии torch в requirements поправить и его). `update.bat` → `scripts/update.py`: копия `config/*.json` в
  `logs/backup`, файлы возвращаются к версии git, `git pull --ff-only`, затем слияние (настройки — владельца, слова словаря —
  из обеих версий, `recent` — владельца), `pip` + `npm install`. Не запускается, пока открыта страница.
- Правила `.bat` проверяет `tests/test_update.py` (chcp, метки для goto, `call` для npm/npx, без `if ( … )`).
  Запустить `.bat` в облаке нельзя — проверяет владелец на ноутбуке.

## Изображения и источники (строго)

- Внешние изображения — ТОЛЬКО public domain или CC0.
- Разрешённые архивы: Wikimedia Commons (лицензию проверять через API metadata, брать
  только PD/CC0), The Met Open Access, Art Institute of Chicago, Smithsonian Open Access,
  Rijksmuseum, Library of Congress (только «no known restrictions», с проверкой).
- Каждый файл → `sources.txt`: URL, автор, дата, лицензия. **Нет лицензии — нет файла.**
- Скачанное кэшируется (`cache/`).
- Карты: современная география — Natural Earth (public domain). Исторические границы
  рисуются кодом по источникам и подписываются «approximate».
- Без лиц реальных живых людей, без чужих логотипов, без кадров из фильмов и чужих каналов.

## Исторический контент (строго)

- Каждый факт, дата, число и цитата — с надёжным источником, который агент **реально
  открыл**: научные книги и статьи (университетские издательства, JSTOR / открытые статьи),
  энциклопедии (Britannica; World History Encyclopedia — с осторожностью), сайты музеев и
  архивов, первоисточники.
- НЕ источники: блоги, форумы, «топ-10» сайты, YouTube, соцсети.
- Каждое утверждение имеет статус: **факт / спорно / легенда / миф**. Спорное и легенды
  так и называются в озвучке.
- Числа (армии, жертвы, население) — диапазоном и с источником, без преувеличений.
- Тяжёлые темы (войны, геноциды, рабство, казни) — уважительно: без смакования насилия,
  без героизации преступлений, без оправдания ненависти; по правилам YouTube о насилии
  и экстремизме.
- Без «презентизма»-оценок без пояснений. Догадки не выдавать за факты.
- Простой язык: понятно школьнику; термины и имена объясняются сразу
  («a pharaoh — Egypt's king»). Простота текста проверяется автоматически.

## Сценарий и удержание

- Хук в первые 15 секунд: интрига / вопрос / неожиданный факт + обещание ответа. Без кликбейта.
- Каждые 60–90 секунд — «повторный хук» (новый вопрос, поворот, открытая петля).
- У каждого видео своя структура (хроника, расследование, «день из жизни», «взлёт и
  падение», «миф vs правда», «5 причин…», «глазами участника», «что если…», «сравнение
  эпох», обратный отсчёт…). Фабрика помнит последние структуры и не повторяет их подряд.
- 5–7 глав, у каждой своя мини-кульминация.
- Финал: вывод + мост к следующей теме. Никаких «подпишитесь» в середине.
- Четыре поднаправления (выбирается для каждого видео): древние цивилизации; войны и
  сражения; загадки и тайны истории; повседневная жизнь людей в прошлом.

## Визуал

- Кадр всегда заполнен: крупный главный объект, фон-«среда», движение камеры.
  Никаких пустых экранов с маленькой фигуркой.
- У каждого кадра свой фон; соседние кадры никогда не одинаковые (ни фон, ни тип кадра).
- Смена картинки каждые 4–8 секунд. Типы кадров: карта с анимированными стрелками и
  границами, таймлайн, архивное изображение с Ken Burns и подписью, сцена-иллюстрация кодом,
  персонаж-рассказчик, сравнение «тогда / сейчас», цитата из первоисточника, схема
  (битвы, города, торговые пути), инфографика с числами.
- Субтитры снизу: 2 строки, крупно, с подсветкой слова + файл `.srt`. Всё важное —
  в безопасной зоне.
- Единые палитры и шрифты — в `video/src/style.ts`. Стили меняют палитру, шрифт и
  обработку картинки, но **тексты (заголовки, подписи, субтитры) всегда чёткие —
  отдельным слоем поверх обработки**.
- Стиль и голос хранятся в настройках и могут меняться для отдельного видео.

## Технические уроки (это уже ломалось — не повторять)

- Windows: `setup.bat` + `start.bat` + `update.bat` (git pull). `.bat` — в CRLF, первая
  строка после `@echo off` — `chcp 65001 >nul`; внутри `if ( … )` не писать скобки в `echo`.
- Claude Code ставить через `winget install Anthropic.ClaudeCode` (npm-версия даёт
  «claude.exe is not a valid application»).
- Скачанные `.bat` блокирует Smart App Control → в README: «Открыть в терминале» →
  `Get-ChildItem -Recurse | Unblock-File` → `.\setup.bat`.
- Папка проекта — на диске C:, не Рабочий стол / OneDrive, без кириллицы в пути.
- Медленный интернет: pip с `--resume-retries 100 --timeout 120`; PyTorch по умолчанию
  обычный (≈200 МБ), версия для видеокарты — отдельным `install_gpu.bat`; модели
  скачиваются заранее отдельной командой с докачкой.
- Рендер Remotion: на Windows сначала `--gl=angle`, затем `swiftshader`; на Linux без
  GPU — `swiftshader` / `egl` (**НЕ `swangle`** — в 4 раза медленнее).
- Шум / зерно — готовые картинки-текстуры, а не `feTurbulence` в каждом кадре.
- Итоговый файл — H.264 **yuv420p** (не yuvj420p) с `-movflags +faststart`.
- Громкость −16…−13 LUFS, пики ≤ −1 dB. Видео = звук = сумма кадров. Субтитры = текст на 100 %.
- Рендер по главам (параллельно, с продолжением после сбоя); показывать оценку времени.
- Упавший шаг повторяется до 3 раз; лог — на русском.

## Архитектура

- **Скрипты (не агенты)**, папка `factory/`: озвучка, произношение, время слов, загрузка и
  проверка лицензий изображений, рендер по главам, склейка, проверки, нарезка Shorts, упаковка.
- **Субагенты** (`.claude/agents/`, минимум инструментов, **НИКОГДА не задают вопросов
  владельцу**): idea-researcher, outline-writer, scriptwriter, fact-checker,
  image-researcher, storyboard-agent, shorts-editor, packager, quality-reviewer.
  Результат агента — файл JSON, который скрипт проверяет по схеме.
- Состояние каждого видео — `output/<дата>_<тема>/state.json`; каждый шаг сценария
  работы ждёт решения владельца (кроме шага «Производство»).

## Главы с таймкодами

- `description.txt`: первая строка «0:00 …», минимум 3 главы, каждая ≥ 10 с, по возрастанию.
- Время глав — из реальной озвучки (время первого слова главы), не из оценок.
- Названия глав ≤ 40 символов, короткие и интригующие.
- Проверка: таймкоды совпадают с началом глав в `video.mp4` (± 1 с); то же для `chapters.json`.

## Критерии «готово»

Звук и картинка синхронны; субтитры без сдвига; текст не выходит за кадр; у каждого
изображения есть PD/CC0-лицензия в `sources.txt`; каждый факт с источником и статусом;
фоны и типы кадров не повторяются подряд; нет пустых кадров; громкость ровная, нет
обрезанных слов; видео точно соответствует подтверждённой раскадровке; Shorts
самодостаточны и с хуком.

## Выход (в папке видео)

`video.mp4`, `thumbnail_1..3.png`, `title.txt` (3 варианта), `description.txt` (с главами),
`chapters.json`, `tags.txt`, `captions.srt`, `sources.txt`, `script.txt`, `outline.json`,
`storyboard.json`, `shorts/short_1..5.mp4` (+ названия / описания).

## Разработка

- Разработка идёт в облачном Linux без видеокарты; ноутбук владельца — Windows 11.
  `.bat`-файлы и ускорение на видеокарте здесь проверить нельзя — честно говорить об этом
  и просить владельца запустить их у себя.
- Проверка окружения: `python scripts/check_env.py` (на Windows — `check_env.bat`).
- Автотесты: `pytest` (с озвучкой: `pytest -m slow`; без неё: `pytest -m "not slow"`).
- Проверка кода видео: `cd video && npm run check` (TypeScript + правила Remotion).
  Один кадр для просмотра: `npx remotion still <id> out/x.png --frame=N`.
  Тестовый лист — `Library-Sheet`, демо-ролик — `python scripts/make_library_demo.py`.
- В облаке PyTorch ставится с PyPI (`uv pip install torch`): файловый сервер pytorch.org
  (download-r2.pytorch.org) в окружении закрыт.
- Папка `headroom/` (git-подмодуль) к фабрике не относится — не трогать.
